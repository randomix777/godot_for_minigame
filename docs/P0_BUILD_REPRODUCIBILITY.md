# P0 Build Reproducibility Assessment

## Can the Release be Fully Rebuilt from Source?

**Answer: Yes, with caveats.**

### What CAN be rebuilt from source

| Artifact | Build Method | Script | Reproducible |
|----------|-------------|--------|--------------|
| WASM template bundle | `scons` from Godot source | `scripts/build_wasm_template.sh` | ✅ Fully |
| Plugin ZIP package | `zip` from source tree | `scripts/package_plugin.sh` | ✅ Fully (timestamp-normalized) |
| Template ZIP bundle | `zip` from build output | `scripts/build_wasm_template.sh` | ✅ Fully (timestamp-normalized) |
| GDScript files | Authoring | Manual | N/A (source of truth) |
| JS bridge files | Authoring | Manual | N/A (source of truth) |
| template.json | Generated during build | `build_wasm_template.sh` | ✅ Fully |
| Plugin release | Tag-driven CI | `release-plugin.yml` | ✅ Fully |

### What CANNOT be rebuilt from source alone

| Artifact | Reason | Mitigation |
|----------|--------|------------|
| `engine/godot.zip` (PCK) | Generated by Godot headless `--export-pack` from user project | Deterministic for same project + Godot binary; not independently reproducible |
| Placeholder PNG images | Generated by GDScript at export time | Deterministic code; same inputs → same output |
| Template-substituted JSON | Variable replacement at export time | Deterministic code; same inputs → same output |

### Build Prerequisites

```
# For WASM template build:
- Git (clone Godot source)
- Python 3.12+ (scons build system)
- SCons 4.9.1 (build tool)
- Emscripten SDK 4.0.3 (emsdk install + activate)
- Brotli (WASM compression)
- jq (JSON manipulation)
- unzip (template validation)
- wasm-validate (WABT toolkit)
- xxd (hex inspection)

# For plugin packaging:
- Git
- jq
- zip

# For CI export smoke test:
- Godot 4.6.1-stable (Linux headless)
- brotli, jq, wabt (validation tools)
- Node.js (JavaScript tests)
- @ttmg/cli (TikTok-specific only)
```

### Build Environment Matrix

| Component | OS | CI Runner | Local Script |
|-----------|-----|-----------|-------------|
| WASM template build | Linux (Ubuntu) | `build-template.yml` | `build_wasm_template.sh` |
| Plugin packaging | Linux (Ubuntu) | `release-plugin.yml` | `package_plugin.sh` |
| Export smoke test | Linux (Ubuntu) | `smoke-test-export.yml` | Manual (requires Godot) |
| Template verification | Linux/macOS | CI step | `verify_wasm_template.sh` |

### Reproducibility Controls

1. **Timestamp normalization**: Both `package_plugin.sh` and `build_wasm_template.sh` set all file timestamps to `198001010000` and permissions to `0644` before zipping, ensuring identical bytes from identical sources.
2. **ZIP member ordering**: Files are sorted with `LC_ALL=C sort` before `zip`, preventing filesystem-order variation.
3. **Fixed ZIP flags**: `-X` (no extra file attributes) and `-9` (maximum compression) are used consistently.
4. **Brotli quality**: `--quality=11` (maximum) is specified explicitly.
5. **scons flags**: All build parameters are hardcoded in the script, not read from environment.

### Verification Commands

```bash
# Verify a built template bundle:
scripts/verify_wasm_template.sh path/to/template.zip

# Verify the plugin package:
cd dist && sha256sum -c godot_mini_game_v0.3.0.zip.sha256

# Rebuild from source (template):
scripts/build_wasm_template.sh 4.6.1-stable 4.0.3

# Rebuild from source (plugin package):
scripts/package_plugin.sh
```

### Known Gaps

1. **No local export smoke test script**: The export smoke test requires Godot headless and is only automated in CI. A local reproduction script would improve developer experience.
2. **scons version pinned in CI only**: `pip install scons==4.9.1` is in the workflow but not enforced in the local build script.
3. **Node.js version**: CI uses the runner's default Node.js. The JavaScript tests (`test/*.test.mjs`) may have implicit version requirements.
4. **Cross-platform ZIP**: The plugin ZIP is built on Linux. Building on Windows/macOS should produce identical archives thanks to timestamp normalization, but this is not verified in CI.
