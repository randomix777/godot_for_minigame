## Fix Applied During P1

### godot.js CRLF Line Ending Issue

**Problem**: The bundled `godot.js` was committed with CRLF (`\r\n`) line endings. The `_patch_godot_js()` function in `exporter.gd` constructs patch patterns using LF (`\n`) only, causing `content.find()` to fail with "缺少 WebAssembly wrapper 补丁锚点".

**Root cause**: Git on Windows with `core.autocrlf=true` converted line endings during checkout. The file was committed with CRLF but `template.json` recorded the LF hash.

**Fix applied**: Converted `godot.js` from CRLF to LF using PowerShell:
```powershell
$content = [System.IO.File]::ReadAllText($filePath)
$content = $content.Replace("`r`n", "`n")
[System.IO.File]::WriteAllText($filePath, $content, [System.Text.UTF8Encoding]::new($false))
```

**Result**: 
- File size: 284,188 → 283,251 bytes (937 CRLF chars removed)
- SHA-256: `e37ce8d7...` → `fd8265ee...` (matches original template.json)
- Export now succeeds with all 7 stages

**Recommendation**: Add a `.gitattributes` entry or pre-commit hook to prevent CRLF in engine binaries.
